# 论文要点总结：动态触觉驱动的故障诊断与闭环恢复

## 一、论文定位

本文面向接触密集的夹爪操作，研究以下核心问题：**如何利用动态触觉理解接触故障，并结合历史恢复情况实现自主纠正？**

这一问题包含三个相互关联的难点：

1. **动态接触状态难以直接理解。** 连续的时序触觉信号包含接触与受力变化，但需要形成简洁、具有物理含义的语义表达，才能支持故障诊断与恢复推理。

2. **局部接触现象难以直接确定恢复策略。** 触觉描述以左指传感器局部坐标系为参考，需要结合视觉与夹爪姿态解释全局空间中的故障；恢复方向和程度还需要根据此前恢复操作的反馈不断修正。

3. **故障恢复难以与任务执行协调。** 机器人需要在动作执行过程中及时发现异常，自主决定何时进入恢复、何时结束恢复，并在必要的多轮恢复后继续原任务。

## 二、三个核心贡献点

### 1. 离散化的触觉元描述

**本文提出一个轻量化触觉描述器，将连续的双指时序触觉信号离散为元触觉描述文本，以少量元字段覆盖夹爪操作中的大部分动态接触状态。** 描述器通过空间特征提取与时序卷积聚合，预测接触面积、三轴受力和旋转五个元字段的离散标签，并生成触觉描述文本。其中，受力标签表达双指同向、异向及法向强弱差异，旋转标签表达接触平面内的旋转状态，为后续故障诊断与恢复策略提供具有物理含义的语义输入。

### 2. 基于触觉的故障诊断和恢复推理方法

**本文提出基于触觉元描述的故障诊断和恢复推理方法，将局部触觉元描述解释为全局空间中的接触故障，并利用历史恢复反馈更新后续策略。** 故障诊断结合视觉信息与左指传感器局部坐标系下的触觉描述，识别全局坐标系下接触故障；恢复推理通过理解历史恢复计划及其失败原因，确定下一步恢复策略。

### 3. 执行与恢复的触觉闭环框架

**本文提出触觉驱动的执行与恢复闭环框架，自主判断恢复的启动与结束，并在故障纠正后继续原任务。** 本框架在动作执行期间异步评估执行状态与恢复进度，及时触发或终止恢复，实现执行与恢复阶段的自主切换，并结合历史恢复反馈开展多轮恢复，恢复完成后继续执行原任务。

## 三、故障理解与恢复历史的逻辑

**故障理解结合当时的视觉与局部触觉，将接触异常解释为全局参考系下的故障语义，为恢复历史提供可跨时刻比较的反馈。** 它使故障诊断与历史恢复推理形成直接联系：先解释接触异常的空间含义，再关联已执行恢复操作及其结果，确定下一步恢复策略。

Touch 以左指传感器局部坐标系为参考。夹爪姿态改变后，局部坐标轴在全局空间中的方向也随之改变，因此相同的 Touch 标签在不同时刻可能具有不同的全局方向含义。如果历史仅保留 Touch 文本，而没有保留当时的图像、夹爪姿态及坐标关系，当前观测未必足以还原过去的接触含义，进而影响跨轮恢复结果的比较。

故障理解在每次观测时结合当时的视觉、姿态和任务目标，将局部接触证据凝练为全局故障描述，再与此前已执行的 plan 配对保存。历史推理因而能够比较“执行了什么恢复操作—随后仍存在什么故障—下一步应怎样恢复”，减少反复从历史原始观测中重建空间语义的需要。全局参考主要统一 failure 的方向语义；plan 的腕部旋转和夹爪距离仍遵循各自定义的执行参考。

这一作用应表述为**为恢复历史提供统一空间参考与任务相关语义**，不能表述为模型无法理解局部坐标系描述。若提供完整的历史图像、姿态和坐标信息，其他方法也可能解释局部触觉。故障理解也不只是坐标变换：局部受力是否对应夹取位置偏差、力度异常或姿态偏差，还需要结合视觉与任务需求判断。其对后续恢复决策的实际价值需通过历史表示对照实验验证。

## 四、后续实验部分的设计与说明

### 4.1 文本接口与字段设计

本项目将 Touch、failure 和 plan 采用结构化文本表达，作为模型训练、历史记录和动作执行的统一接口。字段布局、文本格式及语法约束在实验设置中说明。

**手指传感器身份与方向参考：**

触觉元描述统一以左指传感器的局部坐标系为方向参考。Fx/Fy 的正负、同向与异向均按左指传感器的局部切向轴定义，Fz 表达法向受力状态与双指受力幅值差异。`rotation` 中的 `clockwise` 与 `counterclockwise` 分别表示左指传感器参考视角下的顺时针与逆时针旋转，`none` 表示无旋转；具体观察方向需在标注协议中固定并配图说明。

Touch 以左指传感器局部坐标系表达双指接触状态；failure 中的位置、切向受力、受力失衡侧与旋转方向，以及 plan 中的水平和垂直移动方向，按固定全局坐标系定义。plan 的 rotate 则表示夹爪绕末端腕部旋转关节轴的顺时针／逆时针运动。故障诊断结合视觉中的夹爪与物体姿态，将左指传感器局部触觉证据解释为全局故障状态。左指传感器局部坐标系与夹爪坐标系应明确区分，其与夹爪、相机及全局坐标系的关系需在实验标定说明和示意图中明确。

论文版 Touch 最终采用 area、Fx、Fy、Fz 和 rotation 五个元字段。

| 元字段 | 类别 | 含义 |
| --- | --- | --- |
| area | `none / small / medium / full` | 接触面积状态 |
| Fx | `negative / near_zero / positive / pos_neg / neg_pos` | 以左指传感器局部 X 轴为参考的双指受力方向组合 |
| Fy | `negative / near_zero / positive / pos_neg / neg_pos` | 以左指传感器局部 Y 轴为参考的双指受力方向组合 |
| Fz | `near_zero / negative / left_stronger / right_stronger` | 法向受力状态及双指负向受力强弱差异 |
| rotation | `none / clockwise / counterclockwise` | 以左指传感器为参考的平面内旋转状态 |

Fx 与 Fy 中，`positive` 表示左右传感器均为正向受力，`negative` 表示均为负向受力，`near_zero` 表示均近零；`pos_neg` 表示左正右负，`neg_pos` 表示左负右正。左右顺序固定为传感器身份，不表示画面中的运动方向。

Fz 中，`near_zero` 表示双指法向受力均近零；`negative` 表示存在负向受力，但左右没有明显强弱差异；`left_stronger` 表示左指 Fz 明显更负，即负向受力幅值更大；`right_stronger` 表示右指负向受力幅值明显更大。这两个强弱标签按固定传感器身份定义，不表示全局空间中的左右方向，也不表示异向受力。

论文版 failure 采用 grasp_position、shear、grasp_force、grasp_balance 和 rotate 五个字段。其作用是结合视觉信息与左指传感器局部坐标系下的触觉元描述，推理全局坐标系下的故障状态，为定位可能原因和选择恢复动作提供依据。area 为 grasp_position 提供接触证据；Fx 与 Fy 的同向受力为 shear 提供证据；Fz 为 grasp_force 和 grasp_balance 提供法向受力及双指强弱差异证据；Fx 与 Fy 的异向受力以及 rotation 共同为 rotate 提供证据。

| failure 字段 | 含义 | 类别 |
| --- | --- | --- |
| grasp_position | 全局坐标系下的夹取位置偏差 | `too left / too right / too front / too back / too high / too low / appropriate` |
| shear | 同向切向受力相关故障在全局坐标系下的方向 | `front / back / left / right / up / down / none` |
| grasp_force | 夹取力度是否合适，主要依据法向受力与任务需求判断 | `too small / too large / appropriate` |
| grasp_balance | 双指夹取受力是否失衡，以及全局坐标系下受力偏大的一侧 | `front / back / left / right / up / down / appropriate` |
| rotate | 相对于目标姿态的偏航、俯仰或横滚偏差，按全局固定轴定义，综合平面内旋转与双指异向受力证据 | `yaw_pos / yaw_neg / pitch_pos / pitch_neg / roll_pos / roll_neg / none` |

grasp_position 使用带 `too` 的位置偏差表述，`appropriate` 表示夹取位置合适。grasp_position、shear 与 grasp_balance 的前后左右上下均对应固定全局坐标轴的方向，具体对应关系需在标定示意图中明确，不能按画面中的左右解释。grasp_force 用太小、太大、正好描述夹取力度，属于不带空间方向的量级判断。

grasp_balance 与 grasp_force 分开表达：前者描述双指受力失衡，后者描述整体夹取力度；两者可以同时异常，例如整体力度过大且一侧受力明显偏大。grasp_balance 使用前后左右上下六个方向，以夹取中心为位置参考，表示受力偏大的接触位于全局空间中的哪一侧；例如 `left` 表示全局约定的左侧接触受力偏大，不表示力矢量指向左侧，也不固定对应左指传感器。`appropriate` 表示不存在需要纠正的受力失衡。对于斜向接触位置，标注协议需规定主要全局方向的选择规则。

failure 的 rotate 标签采用偏航（yaw）、俯仰（pitch）和横滚（roll）命名，分别对应绕全局固定 Z、Y、X 轴的偏差，`pos/neg` 表示遵循右手定则的正向／负向，`none` 表示无旋转偏差。例如，全局 Z 轴向上时，从上方俯视，`yaw_pos` 为逆时针偏转，`yaw_neg` 为顺时针偏转。此处使用全局固定轴定义偏差，标签排列不表示欧拉角分解顺序。标签描述相对于任务目标姿态的当前偏差，不表示恢复动作方向。

论文版 failure 文本示例：

```text
failure[grasp_position=appropriate; shear=none; grasp_force=appropriate; grasp_balance=appropriate; rotate=pitch_pos]
```

该示例表示夹取位置与夹取力度合适，没有需要纠正的受力失衡或同向切向受力相关故障，但相对于目标姿态存在正向俯仰偏差（绕全局 Y 轴）。

论文版 plan 在水平移动、垂直移动和旋转三个字段的基础上，增加夹爪距离字段，采用 horizontal、vertical、rotate 和 gripper_distance 四个字段。每个字段表达具体恢复动作的方向与程度；不需要执行该动作时使用 `none`。

| plan 字段 | 含义 | 方向类别 | 程度 |
| --- | --- | --- | --- |
| horizontal | 水平移动 | `front / back / left / right / none` | `slightly / moderately / significantly` |
| vertical | 垂直移动 | `up / down / none` | `slightly / moderately / significantly` |
| rotate | 夹爪绕末端腕部旋转关节轴转动 | `clockwise / counterclockwise / none` | `slightly / moderately / significantly` |
| gripper_distance | 调整两指间的开口距离 | `open / close / none` | `slightly / moderately / significantly` |

horizontal 和 vertical 的方向按与 failure 一致的固定全局坐标系定义。plan 的 rotate 仅指夹爪绕夹爪开合关节之前的末端腕部旋转关节轴转动：`clockwise` 表示顺时针，`counterclockwise` 表示逆时针，`none` 表示不转动。顺逆时针需按该关节轴的固定观察方向判定，并在执行接口说明中配图明确。failure 的 rotate 表达全局坐标系下的偏航、俯仰或横滚偏差，plan 的 rotate 表达单个腕部关节的恢复动作，两者不直接共享方向标签。gripper_distance 的 `open` 表示增大两指间距，`close` 表示减小两指间距，`none` 表示保持当前间距，其程度表示间距变化量，不表示直接设置夹取力。

`slightly / moderately / significantly` 分别表示小幅、中等幅度和大幅调整。水平与垂直移动的程度对应位移量，旋转程度对应末端腕部旋转关节的角度变化量，夹爪开合程度对应开口距离变化量；各字段的具体量级需分别在实验设置中定义。论文版文本中，活动字段采用“方向 程度”的形式；方向为 `none` 时不附加程度，表示该字段不执行调整。

### 4.2 恢复历史与闭环实现

恢复历史将已执行的 plan 与随后出现的 failure 配对记录。blackbox 实验应展示历史恢复操作及后续旋转情况如何影响 `moderately` 或 `slightly` 的选择。

当前五任务模型包含动作生成、恢复触发、故障诊断、恢复规划和恢复结束判断（`adjustment_end`）。触觉主要通过诊断、恢复计划和阶段判断影响动作；action 分支没有直接输入 Touch。闭环评估定位在任务执行与恢复阶段层面。

反事实监督、运动历史、动作回放、共享缓存与异步执行协议在对应实验设置中说明。

### 4.3 核心贡献的实验支撑

| 贡献 | 要证明的问题 | 主要实验方向 |
| --- | --- | --- |
| 触觉元描述 | 是否捕获并保留故障恢复所需的动态接触信息？ | 单帧与时序对比、触觉表示对比、元字段消融、不同任务与故障类型覆盖 |
| 诊断与恢复推理 | 故障方向解释是否准确，统一空间语义的历史是否改善恢复决策？ | 全局坐标系下的故障诊断、相机视角与夹爪及物体朝向变化、Touch 历史与全局 failure 历史对照、同故障不同历史对照、blackbox 移动程度选择、真实多次恢复 |
| 执行与恢复闭环 | 恢复启动与终止判断是否改善任务完成表现？ | 无恢复基线、固定终止与学习终止对比、触发延迟、误报漏报、恢复成功率与总体成功率 |

结构化文本的格式选择可通过接口消融、解析率和计划参数准确率补充评估；它属于实验设计与实现说明，不作为摘要后独立贡献或核心优势。

贡献中的效果表述以实测结果为依据。对单一故障—计划对应关系的数据，需增加同故障不同恢复历史的对照及真实多次恢复实验，支撑依据恢复历史更新策略的结论。

### 4.4 故障理解对恢复历史的作用：历史表示对照实验

**实验目的：**验证将历史局部触觉解释为全局故障语义，是否有助于比较跨轮恢复反馈并选择合理的下一步计划，尤其是在恢复过程中夹爪姿态发生变化时。

| 对照组 | 过去各轮的历史内容 | 验证作用 |
| --- | --- | --- |
| 无历史 | 不输入过去恢复记录，仅保留当前观测与当前故障信息 | 判断历史反馈是否有用 |
| 局部触觉历史 | 已执行 plan + 随后观测到的 Touch | 检验仅保存局部接触描述的效果 |
| 全局故障历史（本文） | 已执行 plan + 随后推理得到的全局 failure | 检验统一空间语义的故障摘要对恢复决策的作用 |

**场景设置：**固定相机与全局坐标约定，分别设置夹爪姿态保持不变和跨轮变化的恢复场景，并在未见过的姿态组合上评测。构造两类对照：同一全局故障在不同局部姿态下呈现不同 Touch；相同局部 Touch 在不同姿态下具有不同全局方向含义。全局故障标签须结合真实接触、视觉姿态与任务目标标注，不能只旋转标签便假定故障成立。另设置当前故障相同、过去恢复方向或程度不同的案例，检验历史是否实际改变下一步策略。

**控制条件：**各组使用相同的当前图像、Touch、qpos 和当前故障信息，仅改变过去各轮反馈的保存方式；匹配恢复起点、过去已执行计划、历史轮数、训练数据划分和模型训练配置。各组按对应历史格式训练或适配，避免只在推理时替换输入造成分布偏移。局部 Touch 与全局 failure 的主对照控制相近文本预算；包含历史图像与姿态的组单独报告输入量和推理成本。全局 failure 主结果使用模型实际预测，另记录诊断准确率以分析错误传播。

**评价指标：**在固定历史样本上评估下一步恢复方向与程度的合理性，允许专家确认的多种可行计划；在独立闭环运行中统计恢复成功率、错误方向恢复率、恢复轮数和耗时。重点比较夹爪姿态变化后各组的性能下降，并检查全局故障历史是否相对局部触觉历史更稳健。若丰富的局部历史也能取得相近效果，则进一步比较全局故障摘要的输入成本与推理延迟，不据此宣称局部描述无法被理解。
