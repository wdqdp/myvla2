## B区的组织

顶部将输入分成通用输入与四类额外输入，下方各模块用同样的字母及颜色标明输入，不再逐一绘制输入连线。颜色与字母同时使用，便于缩小阅读及黑白辨认。

| 色块 | 颜色 | 含义 |
| --- | --- | --- |
| C | 蓝 | 通用输入：front/wrist两路当前图像、当前7维qpos、任务指令 |
| T | 绿 | 当前Touch文本 |
| H | 紫 | qpos运动历史H100→11 |
| P | 黄 | 当前plan；没有计划时为none |
| F | 橙 | 当前及历史全局failure序列，不含历史plan或局部Touch |

| 功能 | 输入色块 | 所处阶段/作用 |
| --- | --- | --- |
| need_recovery | C＋T＋H＋P | Execution期间判断是否启动恢复 |
| failure诊断 | C＋T＋H＋P | need触发、动作保持后诊断当前故障 |
| plan规划 | C＋F | 根据全局故障反馈生成新的恢复计划 |
| adjustment_end | C＋T＋H＋P | Adjustment期间判断当前恢复动作是否结束 |
| Action Expert：execution | C | 生成正常任务动作 |
| Action Expert：adjustment | C＋P | 根据当前plan生成恢复动作 |

五项功能由同一个共享VLA完成。failure与plan仍是共享语言解码器的两类调用；需要按先后顺序完成，并不表示新增两套独立模型。

下方从左至右为三个区域：

1. **保持动作并推理：**故障诊断→更新全局failure序列→恢复规划。记忆仅包含failure，plan模块不再输入Touch或历史plan。
2. **阶段判断流：**Execution中启用need；true先进入左侧保持/推理流程，得到plan后切换Adjustment。Adjustment中启用adj；true返回Execution，false继续当前阶段。恢复阶段不直接重新调用failure/plan；残余故障在续执行时再次检测。
3. **动作生成与执行流：**只画一个共享Action Expert，内部两行分别标明Execution与Adjustment的输入。两阶段复用动作专家。

阶段判断流与动作流之间以“异步运行”分隔标记关联，完整图下方的双时间线进一步展示物理动作与状态评估的重叠。need与adj按阶段交替启用；服务器共享模型按请求串行推理，图中异步指机器人执行与后台状态评估任务的协调，不表示三个模块同时占用GPU并行推理。时间线为流程示意，不代表实测频率或耗时。

## 实图占位框与生成

P1F/P1W仍对应同时刻的正面与腕部相机实拍；P2L/P2R对应左右指同步的三帧真实触觉可视化；P3对应真机末端与物体交互近景。沿用`figure_assets/`目录中的`front.png`、`wrist.png`、`tactile_left.png`、`tactile_right.png`和`robot.png`，具体取图建议见[精修版说明](精修版说明.md#占位框建议替换的实图)。

python 论文准备/draw_inference_framework_v3.py --lang both

## 建议图注

**中文：**动态触觉驱动的故障诊断与闭环恢复框架。（a）时序触觉描述器将双指信号编码为离散元描述文本。（b）共享VLA按任务选择输入，完成故障诊断、全局故障历史驱动的恢复规划、阶段判断及动作生成；输入色块标明各模块的条件。need触发后，系统保持动作并完成诊断与规划，再进入Adjustment；adj结束当前恢复后返回Execution。Action Expert在两阶段共享，分别以任务指令或恢复计划为条件。（c）状态评估与物理动作执行异步协调，实现块内中断、恢复与任务续执行。

**English:** Overview of tactile-driven failure diagnosis and closed-loop recovery. (a) A temporal tactile descriptor converts bilateral fingertip signals into discrete tactile text. (b) A shared VLA uses task-specific inputs, indicated by colored chips, for failure diagnosis, recovery planning from global failure history, stage assessment, and action generation. A positive need prediction pauses execution for diagnosis and planning before entering Adjustment; a positive adj prediction returns to Execution. A single Action Expert serves both phases with their respective conditions. (c) State assessment overlaps physical motion, enabling interruption within an action chunk, recovery, and task resumption.
