## 设计与阅读顺序

图采用白底、低饱和蓝/绿/橙三色。绿色表示触觉语义，橙色表示故障与恢复推理，蓝色表示共享模型及动作；红色只用于故障触发事件。上方按“触觉描述—共享模型—故障/历史/计划—动作”阅读，下方改为双时间线，以实际动作与重复状态评估的重叠表达异步执行。

- **(a) 时序触觉元描述：**真实双指信号序列经过逐帧CNN与TCN，输出论文版五字段文本；左指传感器坐标参考单独注明。
- **(b) 共享推理与动作模型：**用一个共享主干和外框保留参数共享关系，将诊断、历史和恢复规划放在同一个橙色区域。历史记录“已执行plan→随后failure”，之后生成下一步plan。动作专家与两个独立阶段判断头仍属于同一共享模型；按任务选择上下文，动作分支的输入不含直接Touch或运动历史。
- **(c) 异步闭环：**上轨是物理动作，下轨是状态评估调用。need触发后截断原动作并保持，完成诊断与规划后执行恢复；end触发后停止当前恢复并返回任务执行。残余故障由续执行时的need评估再次触发。时间线是流程示意，不表示实测耗时、固定调用频率或模型服务器并行推理。

图内保留短标签与关键接口。更详细的输入组合、历史长度和部署协议适合放在正文或补充材料。

## 占位框建议替换的实图

所有图片建议取自同一个有代表性的black_box恢复回合，保证物体、夹爪朝向和故障描述一致。优先选能看出接触或姿态偏差的时刻，裁剪保留夹爪、接触物和相关环境。

| 占位编号 | 位置与建议内容 | 自动替换文件名 |
| --- | --- | --- |
| P1F | 正面相机的一帧实拍，展示夹爪、物体及故障所在区域；建议约16:10横图 | `front.png` |
| P1W | 与P1F同一时刻的腕部相机画面，突出接触局部；建议约16:10横图 | `wrist.png` |
| P2L | 左指传感器同一窗口内的3帧真实网格/力场可视化，横向拼成一个小序列，按时间从左至右排列 | `tactile_left.png` |
| P2R | 与P2L严格同步的右指3帧可视化；两指使用一致的物理量、色标与单位 | `tactile_right.png` |
| P3 | 当前真机交互画面，裁剪突出末端与物体，用于表达动作作用于环境及产生反馈；约2:1横图 | `robot.png` |

P2L/P2R建议展示真实力场热图，并在清晰可辨时叠加稀疏的切向箭头；应与模型实际输入对应。颜色必须代表实际数据，图内小网格图标和空白时间条只是占位示意。若传感器网格为竖向，3个竖向小图横拼可自然适配现有占位框。

图片统一放入当前目录的`figure_assets/`，再运行下方命令。脚本会自动嵌入已存在的图片，保持比例并居中裁剪；不存在的文件继续显示带编号的占位框。根据拍摄画面需要调整裁剪中心时，可在源码的`placeholder()`中修改。换入实图后，框内编号和提示文字会自动消失。

```bash
python 论文准备/draw_inference_framework_v2.py --lang both
```

也可指定其他图片目录：

```bash
python 论文准备/draw_inference_framework_v2.py --lang both --asset-dir /实际图片目录
```

## 建议图注

**中文：**动态触觉驱动的故障诊断与闭环恢复框架。（a）时序触觉描述器将双指接触信号转换为离散元描述文本。（b）共享VLA结合视觉、状态和任务相关上下文，完成故障诊断、基于历史反馈的恢复规划、阶段判断与动作生成；历史将已执行恢复计划与后续故障配对记录。（c）系统在动作执行期间异步评估状态，在异常发生时中断动作并进入恢复，当前恢复结束后继续原任务，并根据后续反馈按需开展下一轮恢复。

**English:** Overview of tactile-driven failure diagnosis and closed-loop recovery. (a) A temporal tactile descriptor converts bilateral fingertip signals into discrete tactile text. (b) A shared VLA performs failure diagnosis, history-conditioned recovery planning, stage assessment, and action generation using task-specific inputs. Recovery memory pairs executed plans with subsequent failure feedback. (c) State assessment overlaps physical motion, enabling interruption within an action chunk, recovery execution, and task resumption. Residual faults can trigger further recovery rounds after execution resumes.
