## B区阅读方式

1. **阶段控制条独立放置。**Execution期间采用need判断，触发后先停止并保持动作，完成failure诊断与plan生成再进入Adjustment；adj触发后返回Execution。
2. **中间是反复执行的判断回路。**获取最新观测→按当前阶段选择need或adj→判断。false返回获取最新观测，继续当前阶段；true发出中断和阶段更新请求。两个头互斥选用，不表示同时计算。
3. **右侧展开动作路径。**共享Action Expert→H30动作块→机器人逐步执行→环境交互。红色中断箭头指向正在物理执行的动作块；不是等待一整个动作块执行完毕，也不是把每次判断作为生成下一动作的前置步骤。
4. **小型重叠示意。**中间下方展示一个动作块执行期间出现多次判断，最后一次true在块内停止。时间点与动作格仅为示意，不代表实测评估频率、延迟或动作步数。
5. **左侧保留诊断与规划。**need触发并保持动作后，故障诊断更新全局failure序列，再生成下一恢复计划。恢复历史仍仅含failure，不含历史plan。

字母与颜色继续表示输入：C为两路当前图像、当前7维qpos和任务指令；T为当前Touch；H为qpos运动历史；P为当前plan；F为当前及历史全局failure。need、adj与failure均为C＋T＋H＋P；plan为C＋F；Action Expert在Execution阶段用C，在Adjustment阶段用C＋P。图中的adj对应`adjustment_end`。

异步含义是物理动作执行与后台观测/评估任务相互重叠。共享模型的推理请求仍按服务端调度串行处理；图中没有设置多个并行计算的共享主干。恢复阶段结束不等于任务完成，残余故障在返回Execution后再次检测。

## 实图替换与导出

继续使用`figure_assets/`中的`front.png`、`wrist.png`、`tactile_left.png`、`tactile_right.png`、`robot.png`。占位框P1F/P1W是同时刻的正面与腕部相机画面；P2L/P2R是同步双指三帧触觉可视化；P3是实际末端与物体交互近景。详细取图建议见[精修版说明](精修版说明.md#占位框建议替换的实图)。

```bash
python 论文准备/draw_inference_framework_v4.py --lang both
```

此命令仅重新导出v4文件，不覆盖v3或其他历史版本。英文PDF适合论文排版，SVG保留可编辑文字与图形。
